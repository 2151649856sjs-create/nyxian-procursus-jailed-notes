# 04 · 它能干什么

这篇回答最常被问的那个问题：**"它能装 IPA 吗？"** —— 以及它的能力边界到底在哪。

> 验证环境：Nyxian `0.11.5 (20261012.26.RELEASE)` / iOS 27.0 Beta 1 (`24A5355q`)

---

## 一、先分清三种"装"

答案完全不同，混在一起就会得出错误结论。

### ① 装到真实 iOS 桌面（像 TrollStore / SideStore 那样）→ **不能**

硬证据：把内层 Nyxian 的主程序搜了一遍字符串：

```
.ipa    出现 0 次
.deb    出现 0 次
.nipa   出现 2 次（其中 kext.nipa 1 次）
.zip    出现 11 次
```

**它压根不认 `.ipa` 这个格式。** 而且它是系统眼里的一个普通 App，借不到特权，
没法往真实桌面注册任意 App。

> **要装 IPA，请用 TrollStore / SideStore / AltStore，那是另一条技术路线。**

### ② 在 Nyxian 内部跑 App（在它自己的窗口里，不是桌面）→ **能，但有限定**

限定是：**要么是你自己编译出来的，要么是 Nyxian 自己的包格式。**

内层程序里的构建产物路径：

```
$(CACHEROOT)/Payload/$(NXDisplayName).app/$(NXExecutable)
$(CACHEROOT)/$(NXExecutable)
$(CACHEROOT)/Payload/$(NXBundleIdentifier).kext/$(NXExecutable)
```

它自己的包格式叫 **`.nipa`**（`kext.nipa` 就在上面这组路径旁边出现）——
**这是 Nyxian 的 "IPA"，不是 `.ipa`。**

能造的项目类型：

```
Application · Utility · Library · Framework · Kext
× 语言：ObjC · Swift · SwiftUI
```

**一句话：它长于"造"，不长于"装别人的"。**

### ③ 装 DEB 包（Procursus / Sileo 那套）→ **能**

实测在容器里装上了 `launchctl`、`uiktools`。
而且**装在容器自己的 rootfs 里**（apt/dpkg + procursus keyring），跟真实系统隔离。

## 二、能力清单（按确定性分三档）

### 一档：实测过的

- 刷入 ROM 并成功引导
- 装 DEB 包
- 容器里的命令行工具：
  `vim`、`curl`、`less`、`mksh`、`zstd`、`xxd`、一组 term 工具、
  **`dropbear`（SSH 服务端）**、`uicache`、`ldid`、`plutil`

> 注意：这些提示了**容器起来之后最实用的入口很可能是 SSH**。
> 至于入口具体在界面上怎么开，本文写作时还没验证 —— 见 [99-未解决.md](99-未解决.md)。

### 二档：官方 README 里打勾的

- **设备上编译**：C / ObjC / C++ / ObjC++ / Swift（整套 LLVM 在手机上跑）
- **链接**成 MachO → **本机签名** → **执行**
- 跑你造出来的 Application / Utility / Library / Framework，**还包括 KEXT**
- **窗口服务器**：guest 的东西以窗口形式跑在 Nyxian 里，不是跑到真实桌面上
- **KEXT 加载链**：验证 kext 签名 → 验证 nyxian trust blob → 加载进地址空间
  → fixup → 跑 initializer
- 一整套**子进程/syscall 补丁**：`posix_spawn` / `posix_spawnp`、`vfork`、`sysctl`、
  tty + `ioctl`、`libproc`、**`task_for_pid` / `task_name_for_pid`**、
  以及 `setuid` / `setgid` 这类凭据 syscall

### 三档：未知 / 没验证

- 别人的 App 能不能弄进来跑
- 终端窗口的入口在哪
- SpringBoard 插件注入到底可不可行（见下）

## 三、它是什么、不是什么

官方给自己定的性是 **`userspace microkernel`（用户态微内核）**。

| | 虚拟机 | Nyxian |
|---|---|---|
| 是否模拟硬件 | 是 | **否** |
| 跑的是什么 | guest 内核 | **真实的 arm64 iOS 二进制** |
| 怎么骗过 guest | 虚拟化硬件 | 在用户态**拦截并转发**系统调用 |
| 能碰到真内核吗 | 不（被 VMM 隔开） | 不（没有特权） |

**它的分层能力：**

- **强项**：跑**你自己的**进程。编译、执行、装包、起 daemon。
- **弱项**：改**别人的**进程 / 系统进程。它的权限模型是自建的，**借不到 iOS 内核特权**。

## 四、关于"能不能做越狱级插件注入"

这是很多人关心的方向。这里只列**可核实的线索**，不下结论：

**指向"有戏"的：**

- `task_for_pid` / `task_name_for_pid` **是被修好的**
  （官方 README 里特意加了一句 "you heard right, that is not a typo"）。
  这意味着容器里的代码**能拿到别的进程的 task port** —— 这是注入的必要条件之一。
  所以这条路**不是一开始就堵死的**。
- 有完整的 KEXT 加载链（验证签名 → 验证 trust blob → 加载 → fixup → 跑 initializer）。

**指向"没戏"的：**

- 官方 README 自己列了**唯一一条当前限制**：**拦不住 arm64 的 `svc` 指令**
  （supervisor call）。原话大意是：guest 如果直接发系统调用、绕过我们的 shim，我们拦不住；
  但"目前不是问题，因为 iOS 进程本来也没权限"。
  → 反过来说，shim 是**可被绕过**的，而且 guest 里的代码可以走到真实内核。
- 第三方资料（**可信度一般，非官方**）描述 Procursus Jailed：
  能装兼容的 DEB 包，但"**需要无限制系统访问的 tweak 不会生效**"。
- 它归根结底是用户态的东西，借不到内核特权。

**结论**：这是个值得**亲手测一次**的问题，别听别人拍。测试思路：
装个简单包，然后看它能不能真的写进 SpringBoard 的进程空间。

## 五、性能与两个现实硬伤

**性能**：syscall 转发 + 没 JIT（未越狱）→ 比原生慢一截。
轻活能干，重活别指望。

**硬伤一（比性能更劝退）**：免费账号 **7 天要重签一次**。
所以它**不可能当"长期稳定的环境"用** —— 每 7 天得连一次电脑，或者靠 SideStore 刷新。

**硬伤二**：它会**发烫**。发烫 → iOS 热降频 → 更卡 → 更烫（正反馈）。
注意**热降频是 iOS 的保护机制，不是故障**。散热建议：拿掉手机壳、别边充边玩、放通风处。

---

## 六、所以它适合拿来做什么

- 在手机上写 / 编译代码，随手跑起来看效果
- 用容器里的命令行：apt 装工具、跑脚本、SSH 进去
- 做 KEXT 相关实验（最接近传统越狱能力的那一块）
- 学习用户态微内核 / syscall 转发这套机制是怎么实现的

**不适合**：当虚拟机用、当 IPA 安装器用、当越狱替代品用。
