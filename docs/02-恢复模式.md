# 02 · 恢复模式（Recovery）

**刷 ROM、改启动配置、看引导日志，全都在这里做。** 所以先把怎么进去搞明白。

> 验证环境：Nyxian `0.11.5 (20261012.26.RELEASE)` / iOS 27.0 Beta 1 (`24A5355q`)

---

## 一、触发机制（这部分是读引导器代码得出的）

引导器在 App 启动时会做一次**按键扫描**，逻辑大致是：

```js
// 来自 https://nyxian.app/bootstrap/JEFI.js（2026-09-23 版本）
var mode = Number(NXVolumeChangeScanner.scanFor(1.5));
if (mode == 2) { 进入 Recovery; return; }
if (mode == 1) { 开启 Verbose Boot; } else { 正常启动; }
```

配合 `LoaderUI.js` 里作者的注释，按键的语义是：

```
button   1 = 音量加
button   2 = 音量减
kind     "tap"    -> 移动光标（在"松开"时触发）
kind     "select" -> 两个音量键同时按住（用于确认）
```

**所以：**

| 按住 | 结果 |
|---|---|
| **音量减** | **进 Recovery** |
| **音量加** | 进 Verbose Boot（黑底滚日志的界面） |
| 什么都不按 | 正常启动 |

**两个关键细节：**

1. **扫描窗口只有 1.5 秒**，而且是在启动画面挂上之后才开始扫的。
   所以必须**按住不放穿过这个窗口** —— 点一下就松手会被当成 `tap`（那是导航，不是进入）。
2. ⚠️ **这个扫描器是靠"音量发生变化"来感知按键的**（注释原文提到它会
   `install the volume pin and hides the HUD`）。
   **这就是最大的坑：如果你的音量已经在最低（或最高），按那个方向不会产生任何变化事件，可能就扫不到。**

---

## 二、正确操作姿势

1. **先把音量调到中间**（大概一半）。别在最低，也别在最高。← 这一步别省
2. 从多任务界面把 Nyxian **彻底划掉**（不是切到桌面，是真杀掉进程）
3. 手指**先按住音量减键不放**
4. 保持按住的同时**点开 Nyxian 图标**
5. **继续按住约 3~5 秒**，直到画面变

**进去长什么样**：黑底、等宽字体，第一行是 `Nyxian Recovery`，第二行带版本号。

### 进不去怎么办

- **改按音量加试一次。** 如果音量加能进 Verbose Boot，说明扫描器是好的，问题在手法；
  如果两个都进不去，那可能是这个原生扫描类在当前系统版本上失效了。
- 确认音量不在极值（见上面第 1 步）。
- 确认真的杀掉了进程，而不是切到后台。

---

## 三、Recovery 里怎么操作

和普通的越狱 Recovery **完全不一样**，先看这个再动手：

| 动作 | 操作 |
|---|---|
| 上下移动光标 | **轻点**音量上 / 音量下（松手时触发） |
| **确认 / 选择** | **两个音量键同时按住** |

> 作者注释写得很清楚：`Select is a both-held overlap, NOT a timed simultaneous tap`
> —— 先按住一个，再在它按着的时候按另一个，没有时间窗口要求。

屏幕上第二行也会提示：`Use volume up/down and hold both volume keys.`

## 四、主菜单

实测（`0.11.5 / 20261012.26.RELEASE`）：

```

Unflash ROM
Nyxian Files

```

### ⚠️ 菜单会随版本变

这一点必须强调，因为它是本文写作过程中亲身踩到的坑：

| 旧版（服务端引导脚本，2026-09-23） | 你现在这台（2026-10-12 构建） |
|---|---|
| 标题 `USBoot Recovery` | 标题 `Nyxian Recovery`（带版本号） |
| `Import code signature` | 移到了别处 |
| `Wipe data / factory reset` | 同左 |
| `USBoot Files` | 改名叫 `Nyxian Files` |
| `System Files` | 同左 |
| `Power off` | 改名叫 `Power Off`（大小写） |
| 没有 | **`Boot Configuration`**（新增） |
| 没有 | **`Wipe cache`**（新增） |
| 没有 | **`Flash ROM`**（新增） |
| 没有 | **`Unflash ROM`**（新增） |
| 共 6 项 | 共 9 项 |

**所以：看到别人教程里的菜单和你不一样，先看版本号，别急着怀疑自己。**

### 几个别乱按的

| 项 | 会做什么 |
|---|---|
| `Unflash ROM` | 把刷进去的 ROM 抹掉 |
| `Wipe data / factory reset` | 删除 `Documents/manifest`。下次启动会重新下载 manifest 并"重新 strap"，等于把引导重来一遍 |
| `Wipe cache` | 清缓存 |
| `System Files` 里的 `Delete` | 真的删文件 |

## 五、Boot Configuration

实测这一版里有 4 项：

```
[ ] / [X]  Load kexts at boot
[ ] / [X]  Obfuscate Log
[ ] / [X]  Filesystem Sandbox
[E]        Entitlements: enforcing
```

`[E]` 表示这一项是个**枚举**，有多个可选值。

### 怎么用

| 项 | 建议 |
|---|---|
| `Load kexts at boot` | **保持打开。** 跑 Procursus、以及以后碰 KEXT / 插件都靠它 |
| `Obfuscate Log` | **排错时关掉。** 顾名思义，开着的时候日志是被混淆的，读不了。关掉才有可读日志 |
| `Filesystem Sandbox` | **先别动。** 开着隔离更严；ROM 自带的 `libroothide` / `libvroot` 本来就是绕沙盒的，手动关掉反而可能改变别的行为，让排查变乱 |
| `Entitlements: enforcing` | **保持 `enforcing`，别降级。** 降了之后诊断会很乱 |

> **关于 `Verbose Boot`**：网上（包括官方 Discord 的公告）提到过
> `Recovery → Boot Configuration → Verbose Boot`。
> 但在 `20261012.26.RELEASE` 这个构建里**没有这一项**。
> 实测这一版的 Boot Configuration 就是上面那 4 项。
> 推测这一版是"一直详细记日志 + 用 `Obfuscate Log` 控制是否混淆"，
> 所以**要读日志就关 `Obfuscate Log`**。这个结论只对当前版本有效。

## 六、日志在哪

从内层 App 的二进制里能读到日志文件名：**`kmsg.txt`** 和 **`kmsg_old.txt`**。

进 Recovery → `Nyxian Files` 可以浏览 App 的主目录，去找这两个文件。
